# Concept Basis — Stack, Queue & Deque

> [!abstract] Minimal spanning set for this topic. One entry per **new idea you have to learn**. If a problem only changes the cost function, the wording, or the edge cases, it is a variation and it lives in the exclusions table at the bottom, not here.

## Inclusion rule

A problem earns an entry only if solving it requires a mental move you did not already have. Not a different signature, not a harder constraint — a genuinely new way of seeing.

> [!example] The test
> "Delete a subarray and the ends squeeze together" is **one** entry. What you learn is: fix the left end, sweep the right end, so `l..mid` is always the deleted block and every possible subarray gets considered. A version where the deletion cost depends on length teaches nothing new — it is arithmetic bolted onto the same move.

## Mechanism axes

> [!info] Added retroactively. This was the pilot file, written before the axis-first method existed, so its entries were generated by recall and then pruned. The axes below were reconstructed from the finished file and then tested against it — which is how #24 was found.

| Axis | Values |
|---|---|
| **What is stored** | raw values · indices · prefix sums · `(value, count)` pairs · a suspended frame · the cleaned output so far |
| **What triggers a pop, and why** | a match · a domain collision rule · domination by the incoming element · index expiry · **satisfaction** (this candidate has served its purpose) |
| **Is each token's effect determined?** | yes, one outcome per symbol · **no, ambiguous** — the token could act several ways, so you carry a *range* of reachable states rather than one |
| **Where the answer is read** | the popped element · what survives at the end · a counter accumulated across pops · the stack's depth |
| **Ends used** | one (stack) · both (deque) · opposite ends for insert and remove (queue) |
| **What the stack replaces** | nothing — it is the model · the recursion call stack · a sort inside a loop |
| **Assumption that breaks** | sliding window breaks under negatives · a single depth counter breaks under ambiguous tokens · monotonicity breaks when the pop rule is a domain rule, not an ordering |

# STACK

## S1 · Nesting & Matching

The stack *is* the nesting structure. Everything below assumes you already see it that way.

| # | Problem | Source | The new idea |
|---|---|---|---|
| 1 | Valid Parentheses | LC **20** | Push openers, pop and match on close. Stack as a model of nesting depth. |
| 24 | Valid Parenthesis String | LC **678** | **When a token's effect is ambiguous, carry the *range* of reachable states instead of branching.** The `*` can be an opener, a closer, or nothing, so a single depth counter cannot represent where you are. Track `[lo, hi]` — the minimum and maximum open-count still possible — clamping `lo` at zero and failing if `hi` ever drops below it. The generalisation is large and reaches well past strings: **when a decision is undetermined, propagate an interval over the state space rather than exploring both branches.** Two stacks (one of `(` indices, one of `*` indices) is the equivalent solution and the reason this sits in a stack file. |

## S2 · Expression Evaluation

Five distinct moves here, and they are commonly mistaken for one.

| # | Problem | Source | The new idea |
|---|---|---|---|
| 2 | Evaluate Reverse Polish Notation | LC **150** | Operands accumulate, an operator consumes exactly two. Expression evaluation with precedence already removed — the base case. |
| 3 | Basic Calculator II | LC **227** | **Precedence by deferral.** `+`/`-` push a pending term; `*`/`/` resolve immediately against the top. You delay low-precedence work instead of building a parse tree. |
| 4 | Basic Calculator | LC **224** | **Suspend and restore a frame.** On `(` push the accumulated result and sign, reset, then recombine on `)`. #3 *orders* operations; this one *pauses an entire evaluation*. |
| 5 | Decode String | LC **394** | Same suspend/restore shape as #4, but the stacked payload is a multiplier plus a partial string. You learn to carry **construction** state across nesting, not just arithmetic state. |
| 6 | Shunting-yard (infix → postfix) | *classic — no clean judge problem; practise on LC 772* | **The general two-stack parser.** An operator stack plus an output queue, driven by a precedence table. Entries #3 and #4 are ad-hoc shortcuts that work only because LeetCode's calculators have exactly two precedence levels and no functions. Shunting-yard handles arbitrary precedence, right-associativity, unary operators and function calls — and it produces the postfix form that #2 consumes, which is what ties this family together. Worth learning separately because "design an expression evaluator" is a recurring **LLD** question, not only a DSA one. |

| 7 | Asteroid Collision | LC **735** | **Top of stack = most recent unresolved entity**, and the incoming one fights it, possibly annihilating itself. The pop condition is a domain rule, not an ordering — that is what separates this from every monotonic problem below. |

## S7 · Monotonic Stack

The single most important cluster in this file. Five genuinely different uses of the same machine.

| # | Problem | Source | The new idea |
|---|---|---|---|
| 12 | Daily Temperatures | LC **739** | **The core move.** Maintain sorted order; when an incoming element breaks it, everything popped has just found its answer. |
| 13 | Largest Rectangle in Histogram | LC **84** | **Width from the boundary you just exposed.** On pop, the rectangle spans from the new top to the current index — previous-smaller and next-smaller fused into one pass. |
| 14 | Trapping Rain Water | LC **42** | **Horizontal layers instead of vertical columns.** Pop the valley, bound it left and right, fill the slab. A new way of *seeing*, on machinery you already have from #13. |
| 15 | Remove K Digits | LC **402** | **Greedy fused with monotonic popping under a budget.** The stack now enforces lexicographic optimality, not just ordering. |
| 16 | Sum of Subarray Minimums | LC **907** | **Contribution counting.** Rather than enumerate subarrays, ask how many each element is responsible for: `(i - prevSmaller) * (nextSmaller - i)`. |
| 17 | Maximal Rectangle | LC **85** | **Stack a 1D solution across rows.** Treat each row as the base of a histogram whose heights are running column counts, then run #13 once per row. The monotonic stack does not change; what is new is realising a 2D problem can be `n` copies of a 1D one. Developed further in the Matrix basis. |

## S8 · Stack as an Explicit Call Stack

Recursion *is* a stack. These are where you take that stack over manually, which is the price of laziness, resumability, or an iterator interface.

| # | Problem | Source | The new idea |
|---|---|---|---|
| 18 | Binary Tree Inorder Traversal (iterative) | LC **94** | **Replace the call stack by hand.** Descend left pushing as you go, then pop, visit, and turn right. Once you can do this you can pause a traversal mid-flight, which recursion cannot. ↗ developed further in [[Binary Trees]] #1. |
| 19 | Flatten Nested List Iterator | LC **341** | **A stack that survives between calls.** The traversal state lives in the object, so `next()` resumes where the last call stopped and nothing is flattened until asked for. #18 made the stack explicit; this makes it *persistent*. The same laziness over a search you *generate* rather than traverse is [[Backtracking]] #18, and over a tree it is [[Binary Search Trees]] #14. ↗ developed further in the Design basis. |

# QUEUE

> [!info] The plain FIFO queue carries far less of its own weight than the stack — most of its famous uses are developed in other topics. Under the cross-listing rule they are still listed here, because you will meet them while studying queues.

| # | Problem | Source | The new idea |
|---|---|---|---|
| 20 | Design Circular Queue | LC **622** | **Ring buffer arithmetic.** Wraparound with modulo, and the full-versus-empty ambiguity — both indices coincide in each case, so you must either keep a size counter or waste one slot. The only idea in this file that is about the queue *as a container* rather than as a tool. |
| ↗ | BFS / shortest path on unweighted graphs | LC **1091** etc. | The FIFO discipline is what makes the layer-equals-distance argument work. [[Graphs]] #2. |
| ↗ | Binary Tree Level Order Traversal | LC **102** | Queue size at the top of the loop delimits a level. [[Binary Trees]] #2. |

Two more that people expect to find here and should not: **time-expiring windows** (LC 933) are a window driven by an external clock, [[Sliding Window]] #11, and **Josephus-style rotation** (CSES 2163) has an `O(n)` recurrence that removes the simulation entirely, [[Math & Number Theory]] #20. Neither teaches you anything about queues.

# DEQUE — Monotonic

| # | Problem | Source | The new idea |
|---|---|---|---|
| 21 | Sliding Window Maximum | LC **239** | **Two-ended eviction.** Dominated candidates leave from the back, expired ones from the front. A stack cannot do this. The alternative — a max-heap with lazy deletion — is worth knowing for contrast; see [[Heap]] #12. |
| 22 | Longest Continuous Subarray With Absolute Diff ≤ Limit | LC **1438** | **Two deques advanced in parallel** — a max-deque and a min-deque — so the window's range is queryable in O(1) while the window is being resized. |
| 23 | Shortest Subarray with Sum at Least K | LC **862** | **Sliding window breaks under negatives; repair with prefix sums + monotonic deque.** Two things are new: the deque holds *prefix sums* rather than raw values, and front eviction happens **on satisfaction** — once a start index yields a valid subarray it is discarded forever, since a later endpoint could only make it longer. Contrast #21, where front eviction is mere index expiry. |
| ↗ | Jump Game VI | LC **1696** | The deque prunes dominated *DP states* rather than raw values — the first time the thing being evicted is a computed result. [[Dynamic Programming]] #53. Constrained Subsequence Sum (LC 1425) is the same idea; do one, not both. |
| ↗ | 2D Sliding Window Maximum | — | Run #21 along the rows, then along the columns of the result. The dimension-collapse move is [[Dynamic Programming]] #28. |

## Build notes

- **22 native keepers plus 4 cross-listed.** 17 excluded as variations.
- Keeper ratio is roughly **one in two candidates**, which is what puts the full basis near 250 rather than 500.
- LC 862 was missed on the first pass. It surfaced by asking "does the *eviction reason* differ?" rather than "does the data structure differ" — that question is now probe 2 in the shared list.
- **Three entries (#17, #18, #19) were previously exiled** to Matrix, Trees and Design under the old ownership rule. They are back, because a stack file that omits "how to write a traversal without recursion" is not a stack file.

**Step 4B — reverse sweep**

Twenty-five plain-language descriptions were navigated against the family headings. Twenty-three landed correctly. Two findings:

- **"Match brackets, but one symbol could be either an opener or a closer or nothing"** landed nowhere. That is #24, now added to S1. The axis it exposed — **is each token's effect determined or ambiguous?** — was absent, which is unsurprising given this file predated the axis method entirely. An axis table now exists and includes it.
- **"Remove elements that can never be the answer again"** landed on both #12 and #21. Investigated and left alone: that is one idea (domination pruning) legitimately appearing on two containers, not two ideas collapsed into one. A collision is a *signal* to check, not automatically a fault.
- **The re-sweep against CSES, AtCoder and Codeforces added exactly one entry** (#6), and that is a real result rather than a lazy one. LeetCode over-represents stacks and under-represents digit DP, flow and matrix exponentiation. Expect the old source constraint to have cost you heavily on [[Graphs]] and [[Dynamic Programming]], and barely at all here or on Arrays, Binary Search and Linked List.
