# Agentic Problem to Solution Map

> [!abstract] What this is
> Every recurring problem from the Agentic notes, mapped to its standard solutions, what each costs, and when to pick it. The topic notes explain; this is the index for your head: "I see this symptom, these are my moves, this is the one I'd say first." Same idea as [[25 - Problem to Solution Map]] for classic HLD.

> [!tip] Revision drill
> Cover the options, read only the problem and signal, say the options and the default out loud, then check.

---

## 1. Should This Be an Agent?

### A task is being built as an agent by default

- **Signal:** "build an agent" for a process whose steps are known.

| Option | Costs you | Pick when |
|---|---|---|
| **Single (augmented) call** | Limited to one step | Most tasks; try first |
| **Workflow** (chain, route, parallelise, orchestrator-workers, evaluator-optimizer) | Less flexible | Steps known in advance |
| **Workflow with one agentic step** | Partial unpredictability | One open-ended step inside a known process |
| **Full agent loop** | Variable cost, latency, harder evals | Steps unknowable, feedback available, can be bounded |
| **Multi-agent** | Several times the tokens, compounding errors | Broad parallel work or clearly separate domains |

- **Default:** lowest rung that passes evals. **Depth:** [[01 - Workflows vs Agents]]

### Errors compound across steps

- **Signal:** long trajectories fail often (0.95¹⁰ ≈ 60%, 0.9⁵ ≈ 59%).
- **Moves:** fewer model-decided steps; validation gates between steps; parallel fan-out instead of long hand-off chains; intent-level tools that do several steps in code.
- **Depth:** [[01 - Workflows vs Agents]], [[05 - Multi-Agent Topologies and Concurrency]]

### Picking the loop shape

| Loop | Costs you | Pick when |
|---|---|---|
| **ReAct** | Drifts on long tasks; re-sends history every step | Short, exploratory tasks |
| **Plan-and-Execute** | Bad plan wastes the run; replans add calls | Longer tasks; plan must stay visible |
| **ReWOO** | Can't adapt mid-run | Predictable tool chains; cost/latency matter |
| **Graph / state machine** (LangGraph) | Framework and design work | Need checkpoints, HITL pauses, deterministic nodes |

- **Depth:** [[02 - Execution Loops and Control Topologies]]

### The agent never stops / repeats the same call

- **Moves:** step cap; token and dollar budget per run; wall-clock timeouts; hash `(tool, args)` to catch repeats and return "you already did this"; explicit finish action; escalation path. Enforced by the runtime, never by the prompt.
- **Depth:** [[02 - Execution Loops and Control Topologies]]

### Self-correction makes answers worse

- **Moves:** correct only against external ground truth (tests, compiler, schema validation, `EXPLAIN`, citation checks); cap attempts; Reflexion-style reflections only when a real failure signal exists.
- **Depth:** [[02 - Execution Loops and Control Topologies]]

## 2. Tools and Actions

### The model picks the wrong tool

- **Signal:** dozens of raw endpoints exposed; overlapping descriptions.

| Option | Pick when |
|---|---|
| **Intent-level tools** (`refund_order` instead of five raw calls) | Known procedures, especially side effects |
| **Route first, then expose only that domain's tools** | Clear domains |
| **Tool retrieval** (top-k tools by embedding) | Large tool catalogues |
| **Sub-agent per toolkit** | Many tools in distinct groups |
| **Better names, when/when-not descriptions, enums** | Always |

- **Depth:** [[03 - Tool Engineering and Action Spaces]]

### Tool arguments are invalid or hallucinated

- **Moves:** strict schemas (constrained decoding) for shape; Pydantic validation for semantics; return validation errors as short observations; ask the user when ids can't be resolved; never let the model supply identity.
- **Depth:** [[03 - Tool Engineering and Action Spaces]], [[00 - LLM Fundamentals for Engineers]]

### A tool error kills the whole run

- **Moves:** errors as observations (code, message, hint); runtime retries transient errors itself; raise only for authorisation, budget and policy failures.
- **Depth:** [[03 - Tool Engineering and Action Spaces]]

### A retry or replay duplicates a side effect (double refund)

- **Moves:** idempotency key generated by the orchestrator from run id + step, stored with the result, sent downstream; state-checked downstream operations; human approval for irreversible actions; compensations for multi-step effects.
- **Depth:** [[03 - Tool Engineering and Action Spaces]], [[09 - Durable Execution HITL and Realtime UX]], [[LLD/Foundations/11 - Idempotency and Retries]]

### Many AI clients need the same integrations

| Option | Pick when |
|---|---|
| **MCP server** (tools, resources, prompts over JSON-RPC) | Many hosts/clients consume the same systems |
| **Plain function tools** | One app, a handful of tools |
| **A2A** (agent cards, tasks) | Delegating long jobs to agents owned by other teams/vendors |

- **Watch out:** malicious or over-privileged MCP servers; allow-list, pin, scope tokens.
- **Depth:** [[03 - Tool Engineering and Action Spaces]]

## 3. Context, State and Memory

### Context keeps growing; agent gets slower, costlier and dumber

- **Signal:** early 15 KB tool payloads still in history at step 12; "lost in the middle".

| Option | Costs you | Pick when |
|---|---|---|
| **Trim tool outputs at the source** | Tool design | Always first |
| **Observation masking** (summarise raw outputs N steps later) | Details need a handle to recover | Tool-heavy runs |
| **Offload to handles + `read(id)` tool** | Extra tool | Big documents, logs, query results |
| **Compaction / summarisation at thresholds** | Extra call; can drop details | Long conversations |
| **Structured state rendered into the prompt** | Schema design | Agents with known sub-goals |
| **Sub-agent isolation** | Extra calls | Messy search-heavy sub-tasks |

- **Depth:** [[04 - State Memory and Context Engineering]]

### Remembering users across sessions

| Tier | Holds | Store |
|---|---|---|
| **Episodic** | Past events | Event log + embeddings |
| **Semantic** | Distilled facts, preferences | Profile store / KG |
| **Procedural** | Learned rules, strategies | Versioned prompt fragments, examples |

- **Write path default:** background consolidation worker, ordered per user; hot-path writes only when needed immediately.
- **Depth:** [[04 - State Memory and Context Engineering]]

### Concurrent sessions overwrite each other's memory

- **Moves:** per-user single-writer queue; compare-and-set with versions; field-level merges; append-only facts resolved at read time.
- **Depth:** [[04 - State Memory and Context Engineering]], [[03 - Concurrency Control]]

### Memory gets poisoned or leaks across users

- **Moves:** persist only validated facts with provenance; hard user/tenant filters before similarity search; TTL and deletion that reaches embeddings; human review for procedural memory.
- **Depth:** [[04 - State Memory and Context Engineering]], [[10 - AI Gateway Security and Guardrails]]

## 4. Multi-Agent

### Choosing a topology

| Topology | Pick when |
|---|---|
| **Router** | Requests fall into clear domains, one specialist each |
| **Supervisor** (hierarchical) | Task needs decomposition and synthesis |
| **Swarm / handoffs** | One specialist at a time owns a conversation |

- **Depth:** [[05 - Multi-Agent Topologies and Concurrency]]

### Sub-agents inherit too much context

- **Moves:** scoped Pydantic task brief in, validated structured result out; never pass the parent transcript; validate at every boundary.
- **Depth:** [[05 - Multi-Agent Topologies and Concurrency]]

### Parallel branches conflict or merge non-deterministically

- **Moves:** explicit reducers (append, union, keyed merge, custom deterministic); sort by stable key before reducing; single-writer fields.
- **Depth:** [[05 - Multi-Agent Topologies and Concurrency]], [[LLD/Concurrency/13 - Designing Thread-Safe Classes]]

### Fan-out trips provider rate limits or blows the budget

- **Moves:** semaphore on concurrent calls; per-branch timeouts and budgets; tolerate partial failure with a threshold; token-aware limits at the gateway.
- **Depth:** [[05 - Multi-Agent Topologies and Concurrency]], [[10 - AI Gateway Security and Guardrails]]

## 5. Retrieval (RAG)

### Answers are wrong even though the document exists

- **Signal:** the fact is in the corpus but never retrieved or retrieved without context.

| Cause | Fix |
|---|---|
| Bad parsing (tables, columns, scans) | Layout-aware parsers, table-to-text, OCR, inspect samples |
| Chunk lacks context | Contextual chunk headers; parent-child retrieval |
| Answer split across chunks | Structure-aware splitting; overlap; return parent section |
| Exact identifiers missed | Hybrid BM25/SPLADE + dense with RRF |
| Right chunk ranked low | Cross-encoder reranking of top 50–100 |
| Conversational follow-up | Query condensation with history |
| Multi-part question | Query decomposition |

- **Depth:** [[06 - RAG Ingestion and Indexing Pipeline]], [[07 - Agentic RAG and Grounding Loops]], [[08 - Vector DB Internals and Hybrid Search]]

### Users see documents they shouldn't

- **Moves:** tenant and ACL metadata on every chunk; filter inside the retrieval query (filter-aware search, never post-filter); per-tenant partitions for large tenants; propagate permission changes as part of freshness.
- **Depth:** [[06 - RAG Ingestion and Indexing Pipeline]], [[08 - Vector DB Internals and Hybrid Search]]

### Small tenants get empty results

- **Signal:** post-filtering global top-k.
- **Moves:** filter-aware single-stage search; brute force over small allowed sets; per-tenant partitions.
- **Depth:** [[08 - Vector DB Internals and Hybrid Search]]

### Stale or deleted documents keep being cited

- **Moves:** content-hash incremental re-ingestion; CDC/webhooks from sources; deletes propagated to every index and cache; doc versions on chunks; TTL metadata.
- **Depth:** [[06 - RAG Ingestion and Indexing Pipeline]]

### Model answers from irrelevant chunks, or loops on missing information

| Option | Pick when |
|---|---|
| **Relevance grading** (small yes/no model, CRAG) | Retrieval is noisy |
| **Capped rewrites (1–2) then deterministic fallback** | Information may be absent |
| **Adaptive retrieval** (skip when not needed) | Mixed chit-chat and knowledge queries |
| **Abstention in the output schema** | Always |

- **Depth:** [[07 - Agentic RAG and Grounding Loops]]

### The question isn't a document question

| Question | Route to |
|---|---|
| Counts, sums, filters over records | Text-to-SQL on a read-only replica with RLS |
| Live state | API tool |
| Recent public info | Web search |
| Multi-hop relationships, corpus-wide themes | GraphRAG / graph queries |

- **Depth:** [[07 - Agentic RAG and Grounding Loops]]

### Citations are fabricated

- **Moves:** chunk ids in context; require per-claim citations; verify ids exist, quotes are verbatim, claims are supported (NLI / small judge); regenerate or drop unsupported claims.
- **Depth:** [[07 - Agentic RAG and Grounding Loops]]

### Vector index doesn't fit in memory

| Option | Saves | Costs |
|---|---|---|
| **int8 scalar quantization** | 4× | Small recall loss |
| **Binary quantization + rescoring** | 32× | Needs rescoring |
| **Matryoshka truncation** | 2–6× | Only for Matryoshka-trained models |
| **IVF-PQ** | 30–60×+ | Approximate distances; re-training on drift |
| **DiskANN** | Most RAM | SSD-bound latency |

- **Depth:** [[08 - Vector DB Internals and Hybrid Search]]

### Changing the embedding model

- **Moves:** new index; dual-write; backfill; shadow-compare retrieval metrics; switch via alias; keep old index for rollback. Never mix models in one index.
- **Depth:** [[11 - Evals Observability and Silent Drift]], [[06 - RAG Ingestion and Indexing Pipeline]]

## 6. Durability, Humans and UX

### A crash mid-run re-pays for inference and duplicates side effects

| Option | Pick when |
|---|---|
| **Durable execution** (Temporal-style replay of recorded activity results) | Business-critical, long-running, many side effects |
| **Per-node checkpoints** (LangGraph + Postgres/Redis) | Agent-centric apps, pause/resume, inspection |
| **Idempotency keys on side effects** | Always, with either of the above |

- **Depth:** [[09 - Durable Execution HITL and Realtime UX]]

### An action needs human approval

- **Moves:** return 202 + run id; pause durably (interrupt / signal); notify reviewer with the exact action; resume from an authenticated webhook; re-validate state on resume; approval timeouts; audit log.
- **Depth:** [[09 - Durable Execution HITL and Realtime UX]]

### The answer feels slow

| Option | Pick when |
|---|---|
| **Stream tokens + progress events (SSE)** | Default for chat and agent UIs |
| **WebSockets / WebRTC** | Client also streams (voice, cancel mid-stream) |
| **Decouple the run from the connection; resumable event ids** | Mobile or flaky clients |
| **Shorter outputs, fewer sequential steps** | Real latency, not just perceived |

- **Depth:** [[09 - Durable Execution HITL and Realtime UX]], [[12 - LLM Cost and Latency Economics]]

### Voice agent talks over the user

- **Moves:** VAD-triggered barge-in that flushes every audio buffer, cancels LLM generation and TTS, and truncates history to what was spoken; semantic end-of-turn detection; WebRTC transport; streaming at every stage.
- **Depth:** [[09 - Durable Execution HITL and Realtime UX]]

## 7. Security and the Gateway

### Provider outage, keys everywhere, no control over spend

- **Move:** an AI gateway owning credentials, routing, retries and fallbacks (evaluated, same tier, residency-aware), hedging for idempotent calls, token-aware limits, budgets, caching, tracing and redaction.
- **Depth:** [[10 - AI Gateway Security and Guardrails]]

### One tenant's big prompts exhaust the token quota

- **Move:** token bucket in tokens: reserve input + max output before the call, reconcile with actual usage after; per tenant, per user, per feature; global cap under the provider limit; Redis-backed across nodes.
- **Depth:** [[10 - AI Gateway Security and Guardrails]]

### The agent reads untrusted content and could be hijacked (indirect prompt injection)

| Layer | Control |
|---|---|
| **Remove a leg** | No single agent gets private data + untrusted content + an outbound channel |
| **Identity and authorisation** | From the session, checked in services |
| **Least privilege** | Scoped, short-lived credentials per agent/task |
| **Capability separation** | Quarantined model for untrusted text (no tools); privileged planner never sees raw text |
| **Egress control** | Domain allow-lists; strip/proxy links and images in output |
| **HITL** | Approval for high-impact actions |
| **Classifiers and prompt hygiene** | Probabilistic extra layer, never the boundary |

- **Depth:** [[10 - AI Gateway Security and Guardrails]]

### Running model-generated code

| Option | Pick when |
|---|---|
| **gVisor** | Multi-tenant execution on Kubernetes |
| **Firecracker microVM** | Untrusted code at scale, strongest isolation |
| **Managed sandbox** (E2B-style) | Need an interpreter without running isolation infra |
| ~~Plain container~~ | Trusted code only |

- **Policy:** no network (or allow-list), no secrets, resource and time limits, ephemeral, output treated as untrusted.
- **Depth:** [[10 - AI Gateway Security and Guardrails]]

### PII flowing to providers and logs

- **Moves:** redaction/tokenisation before external calls; provider retention and zero-data-retention terms; data-residency routing; retention and access control on traces; deletion that reaches logs, caches, embeddings, memories.
- **Depth:** [[10 - AI Gateway Security and Guardrails]], [[18 - Security]]

## 8. Quality, Evals and Drift

### "How do you know it works?"

| Tier | Checks | When |
|---|---|---|
| **Deterministic** | Schema, router label, tool and args, limits | Every commit |
| **Trajectory** | Right tools, order, no forbidden actions, step budget | Agent changes; sampled prod |
| **Outcome** | Real environment state, reference answers, RAG faithfulness | Releases, nightly, sampled prod |

- **Depth:** [[11 - Evals Observability and Silent Drift]]

### The LLM judge can't be trusted

- **Moves:** binary specific rubrics; reference answers or source context; evaluate both orders (position bias); different model family (self-preference); length control (verbosity); calibrate against 100–200 human labels.
- **Depth:** [[11 - Evals Observability and Silent Drift]]

### System returns 200 OK but is wrong or looping

- **Moves:** alert on task success, cost per task, steps per task, tool error rate, abstention and truncation rates; semantic circuit breakers to a fallback; pinned model versions; contract tests on tools.
- **Depth:** [[11 - Evals Observability and Silent Drift]]

### Semantic cache returns the wrong answer

- **Moves:** never semantically cache actions or transactions; exact-match caching for deterministic calls; scope keys by tenant/user/locale/data version; entity checks plus high thresholds; TTLs; measure false-hit rate.
- **Depth:** [[11 - Evals Observability and Silent Drift]]

### Where did this bad answer come from?

- **Move:** one trace per run, one span per LLM/tool/retrieval step with model, tokens, cost, prompt version, chunk ids, finish reason (OpenTelemetry GenAI conventions); every incident becomes an eval case.
- **Depth:** [[11 - Evals Observability and Silent Drift]]

## 9. Cost and Latency

### Cost per task is too high

| Lever | Pick when |
|---|---|
| **Prompt caching** (stable prefix first, variable last) | Long system prompts, tools, reference docs, multi-turn agents |
| **Context compaction** | Agent input growing quadratically with steps |
| **Routing / cascades** | Most traffic is easy |
| **Batch API** | Offline work (evals, backfills, enrichment) |
| **Fewer steps / intent tools / workflows** | Agents with predictable procedures |
| **Shorter outputs, reasoning-effort control** | Output and reasoning tokens dominate |
| **Distil to a small model** | Narrow, high-volume task |

- **Depth:** [[12 - LLM Cost and Latency Economics]]

### Prompt caching isn't hitting

- **Signal:** timestamps, user names or request ids at the top; tools reordered; history rewritten every turn.
- **Moves:** stable content first; round dates; fixed tool order; compact in chunks at thresholds; prefix-aware routing when self-hosting.
- **Depth:** [[12 - LLM Cost and Latency Economics]], [[13 - GPU Serving and Disaggregated KV Cache]]

### API or self-host?

| Option | Pick when |
|---|---|
| **API** | Variable/modest volume, need frontier quality, small team |
| **Self-host** | High sustained utilisation, residency/privacy, custom or fine-tuned models |
| **Hybrid** | Frontier API for hard steps, self-hosted small models for volume |

- **Depth:** [[12 - LLM Cost and Latency Economics]], [[14 - Quantization Decoding and VRAM Math]]

## 10. Serving Infrastructure

### Concurrency is limited / requests OOM on long contexts

- **Signal:** KV cache (~0.3 MB/token for a 70B GQA model) fills GPU memory; preemptions.

| Option | Effect |
|---|---|
| **PagedAttention** (vLLM) | Removes KV fragmentation; more sequences fit |
| **FP8 / INT8 KV cache** | ~2× tokens in flight |
| **GQA / MQA / latent-attention models** | Smaller KV per token |
| **Tiered / offloaded KV** (CPU, SSD, remote via LMCache/Mooncake) | Keep reusable prefixes without HBM |
| **Admission control, max context limits** | Stop over-admission |
| **More GPUs / tensor parallel** | More memory per replica |

- **Depth:** [[13 - GPU Serving and Disaggregated KV Cache]], [[14 - Quantization Decoding and VRAM Math]]

### Token streams stutter when long prompts arrive

| Option | Pick when |
|---|---|
| **Continuous batching** | Always (baseline) |
| **Chunked prefill** | Mixed long-prompt and streaming traffic |
| **Disaggregated prefill/decode pools + KV transfer over RDMA** | Large scale, strict TTFT and ITL SLOs, prefill-heavy workloads |

- **Depth:** [[13 - GPU Serving and Disaggregated KV Cache]]

### Agent steps re-prefill the whole history every call

- **Signal:** round-robin load balancing across GPU nodes.
- **Moves:** prefix caching (RadixAttention / automatic prefix caching); prefix-aware routing scored by cache hit minus load; session stickiness; distributed KV cache to fetch instead of recompute.
- **Depth:** [[13 - GPU Serving and Disaggregated KV Cache]]

### Model doesn't fit, or decode is too slow

| Option | Costs you | Pick when |
|---|---|---|
| **FP8 weights + activations** | Needs supported hardware | High-throughput serving |
| **INT4 weight-only (AWQ/GPTQ)** | Reasoning quality loss | Memory-bound; simple, high-volume steps |
| **Speculative decoding** (EAGLE, draft model, n-gram) | Draft overhead; less gain at high batch | Latency-sensitive, lower batch |
| **Tensor / pipeline / expert parallelism** | Interconnect requirements | Model bigger than one GPU |

- **Rule:** keep planners and reasoners at FP8/BF16; evaluate quantized models on your trajectories.
- **Depth:** [[14 - Quantization Decoding and VRAM Math]]

### Structured output inflates time to first token

- **Moves:** pre-compile and cache grammars for static schemas (XGrammar-style engines); small, reused schemas; reasoning fields before answer fields.
- **Depth:** [[14 - Quantization Decoding and VRAM Math]]

### Sizing a deployment

- **Formula:** VRAM ≈ weights (params × bytes) + KV (per-token bytes × tokens in flight) + ~10–20% overhead; cost per 1M tokens ≈ GPU $/hour × GPUs ÷ (aggregate tokens/s × utilisation × 3600 ÷ 10⁶).
- **Depth:** [[14 - Quantization Decoding and VRAM Math]]

## 11. Adapting the Model

### Prompting isn't enough

| Need | Move |
|---|---|
| Changing or private **facts** | RAG, not fine-tuning |
| Reliable **format, style, domain behaviour** | SFT / LoRA |
| **Cheaper** narrow high-volume task | Distil into a small model |
| Better **tool-use decisions** in your environment | SFT on verified trajectories, then RLVR |
| Better **reasoning** on checkable tasks | RLVR (GRPO) or more test-time compute |
| **Tone / preference** alignment | DPO |

- **Depth:** [[15 - Post-Training and Model Adaptation]]

### Fine-tuned model copies the teacher's bad habits

- **Moves:** keep only outcome-verified, minimal-step, policy-clean trajectories (rejection sampling); evaluate on held-out tasks vs teacher; optional RLVR after SFT.
- **Depth:** [[15 - Post-Training and Model Adaptation]]

### RL training "succeeds" but the model got worse

- **Signal:** reward hacking: passes the verifier without solving the task.
- **Moves:** robust verifiers, held-out tests, length penalties, KL constraints, trajectory review.
- **Depth:** [[15 - Post-Training and Model Adaptation]]

### Many per-tenant or per-task fine-tunes to serve

- **Moves:** LoRA adapters on one shared base; multi-LoRA serving (S-LoRA paged adapter memory, Punica SGMV kernels); adapter registry and retraining plan on base upgrades.
- **Depth:** [[15 - Post-Training and Model Adaptation]]
