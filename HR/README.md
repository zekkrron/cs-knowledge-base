# HR

> [!abstract] Company-agnostic HR / EM / hiring-manager questions. **Questions only.** Answers wait until [[Resume]] notes exist so STAR stories attach to real bullets, not invented ones.

This is **not** the Temple script. Same list at any product-startup backend loop. Company-specific "why us" is one blank you fill per process, not a second bank.

## How this will get filled

Everything eventually gets STAR (Situation, Task, Action, Result) — including "how do you resolve conflict," which they still want as a *time*, not a TED talk.

When resume notes exist: pick **one primary story** per question family, reuse a story across at most two questions, never force a metric you will not defend. If a question is really a resume excavation, answer from the project file and only keep a 30-second HR wrap here.

Skip brain-teasers ("what animal are you"). They waste prep and almost never show up in a serious backend loop.
